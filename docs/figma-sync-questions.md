# Figma Sync 작업 중 질문 기록

## 결정되어 반영한 항목 (2차)

| 항목 | 결정 | 반영 |
|---|---|---|
| 주소 검색 | Daum 팝업 대신 전체 화면 + Daum 우편번호 embed | `/address-search` (결과 없음은 Daum `onsearch` count 0) |
| 배송지 수정 / 새 배송지 입력 | 모달 → 별도 페이지 | `/addresses/:id/edit`, `/addresses/new?returnTo=` |
| 판매자에게 문의 | 모달 → 별도 페이지 | `/orders/:id/inquiry` |
| 판매 상품 등록 / 판매 정보 수정 | 7단계 위저드 → 단일 스크롤 화면 | `/seller/new`, `/seller/new?edit=` |
| AI 상품분석 | 라우트 추가 | `/seller/new/ai`, `/seller/new/ai/analyzing`, `/seller/new/ai/failed` |
| AI 상품 Q&A | 기능 제외 | 라우트 정의·테스트·이미지 정리, 점검표 계산에서 제외 |
| 도메인에 없는 값 | optional 필드 + Figma 예시 목업, 값 없으면 행 숨김 | `docs/backend-api-requests.md` |

## 남은 질문

- **Figma 화면끼리 예시 값이 다름**: 판매 스케줄은 가디건 39,000원·바구니 23:00 오픈인데, 홈·상품 상세는 42,000원·바구니 완판입니다. 스케줄은 별도 목업(일정 API 응답 가정)으로 두었습니다. 일정 API를 붙일 때 상품 데이터로 통일할지 확인이 필요합니다.
- **카테고리 체계**: Figma AI 분석은 `패션 › 상의 › 니트/스웨터`, 코드는 `의류 / 상의 / 가디건` 형식입니다. 지금은 Figma 경로 3개를 `CATEGORY_PATHS`에 함께 넣었습니다.
- **단일 화면 등록에 없는 기존 입력 항목**: 상품 설명, 브랜드, 추가 정보, 재고 처분 사유, 예상 질문 FAQ는 Figma에 없어 입력란을 뺐습니다. 백엔드에서 필수인지 확인이 필요합니다.
- **판매자 입점 신청의 우편번호 입력 2개**: Figma에는 없지만 신청 API에 우편번호가 들어가서 남겨 두었습니다.
- **홈 마감 시간**: 홈 Figma는 가디건 `01:12:40`, 상품 상세 Figma는 `02:19:57`입니다. 상품 상세 기준으로 두었습니다.
- **판매 상품 등록 후 이동**: 기존처럼 `/seller/published/:id`로 갑니다. Figma `심사 대기` 화면과 같은 곳인지 확인이 필요합니다.
- **테스트**: 단위 테스트 1건(`공통 상품 등록` – `판매 예정` 기대, 실제 `게시 전`)은 이번 작업 전부터 실패합니다. 7단계 위저드·Q&A e2e는 지웠고, 단일 화면 등록 e2e는 아직 없습니다.

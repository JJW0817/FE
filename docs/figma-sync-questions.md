# Figma Sync 작업 중 질문 기록

## 결정되어 반영한 항목 (2차)

| 항목 | 결정 | 반영 |
|---|---|---|
| 주소 검색 | Daum 팝업 대신 전체 화면 + Daum 우편번호 embed | `/address-search` (결과 없음은 Daum `onsearch` count 0) |
| 배송지 수정 / 새 배송지 입력 | 모달 → 별도 페이지 | `/addresses/:id/edit`, `/addresses/new?returnTo=` |
| 판매자에게 문의 | 모달 → 별도 페이지 | `/orders/:id/inquiry` |
| 판매 상품 등록 / 판매 정보 수정 | 7단계 위저드 → 단일 스크롤 화면 | `/seller/new`, `/seller/new?edit=` |
| AI 상품분석 | 라우트 추가 | `/seller/new/ai`, `/seller/new/ai/analyzing`, `/seller/new/ai/failed` |
| AI 상품 Q&A | 기능 제외 | 라우트 정의·테스트·이미지 정리, 점검표 계산에서 제외 |
| 도메인에 없는 값 | optional 필드 + Figma 예시 목업, 값 없으면 행 숨김 | `docs/backend-api-requests.md` |

## 3차 결정 (반영 완료)

- 예시 값은 각 화면 SVG 값 그대로 두고 화면끼리 맞추지 않음 (판매 스케줄은 별도 목업 유지)
- 카테고리는 Figma 체계(`패션 › 상의 › 니트/스웨터`)로 통일, 기존 체계 제거
- 등록 화면: 예상 질문 FAQ 제외, 브랜드는 판매자 정보에서 자동 저장, 상품 설명·추가 정보·재고 처분 사유는 `backend-api-requests.md` "필수 여부 확인 필요"
- 입점 신청 우편번호 입력란 제거, 주소 검색 결과로 자동 채움
- 심사 요청 후 Figma `심사 대기` 화면(`/seller/published/:id`)으로 이동
- 단위 테스트를 새 흐름 기준으로 수정, 등록 화면 e2e 추가

## 남은 질문

- **홈 마감 타이머**: 홈 Figma의 가디건 `01:12:40`은 실시간 카운트다운이라 같은 상품의 상품 상세 남은 시간과 같은 값으로 나옵니다. 홈 전용 목업으로 분리할지 확인이 필요합니다.
- **판매 스케줄 카테고리 문구**: SVG 값 그대로(`의류 / 상의`) 두었습니다. 카테고리 통일과 다르게 보여도 되는지 확인이 필요합니다.
- **기존 e2e(`tests/flows.spec.ts`, `extra.spec.ts`)**: 지금은 없는 미리보기 도구(`로컬 미리보기`)에 의존해 이번 작업 전부터 동작하지 않습니다. 새 `seller-register.spec.ts`만 통과를 확인했습니다.

# Figma Sync 작업 중 질문 기록

## 03 구매와 주문

### 주소 검색 결과 없음 — 구조 변경 필요
- Figma: 전체 화면 주소 검색 UI (`/address-search` 라우트). 검색창 + 빈 결과 상태 + "이렇게 검색해 보세요" 팁 박스.
- 현재 코드: Daum Postcode API 팝업 방식 (`AddressModal` 내 버튼). 전체 화면 없음.
- **질문**: 주소 검색을 Daum 팝업 → 인앱 전체 화면으로 교체할지 결정 필요.
  - 교체한다면: `/address-search?returnTo=...` 라우트 추가, Daum API 연동을 해당 화면으로 이전.
  - 현행 유지라면: 반영점검표 10% 화면은 구조적 차이로 스킵 처리.
- Figma 기준으로 작업 진행 (인앱 전체 화면 추가 방향 권장).



## 05 고객지원과 문의

### 문의 (판매자에게 문의) — 모달 vs 전체 화면 구조 차이
- Figma: `/문의.svg`는 전체 화면으로 표시됨 (헤더 "판매자에게 문의", 상품 요약, 문의 유형 칩, 내용, 사진 첨부 섹션 포함).
- 현재 코드: `OrderContactModal` — `buyer.tsx`의 바텀시트 스타일 모달. 별도 라우트 없음.
- **질문**: 판매자 문의를 전체 화면(`/inquiries/seller/:orderId`)으로 분리할지 결정 필요.
  - 분리한다면: 새 라우트 추가, `OrderContactModal`을 페이지 컴포넌트로 변환, 문의 유형 칩 적용, 사진 첨부 UI 추가 필요.
  - 현행 유지라면: 모달 내에서 가능한 범위(칩 타입 선택 등)만 개선.
- Figma 기준으로 작업 진행 (전체 화면 분리 방향 권장).

### 문의 내역 / 문의 상세 — 목업 데이터 브랜드명
- Figma의 카드에 "LOWFIELD · 소프트 코튼 가디건"처럼 브랜드+상품명 형식 표시.
- 현재 `Inquiry.productName`에 브랜드 정보가 없음 (상품명만 저장).
- **질문**: `Inquiry` 도메인에 `brand` 필드 추가 여부 결정 필요, 또는 `productName`을 "브랜드 · 상품명" 형식으로 저장하도록 변경.

## 07 상품 등록과 판매 관리

### 판매 상품 등록 (`/seller/new`) — WizardPage vs 단일 화면
- Figma: 단일 "판매 상품 등록" 화면 (한 페이지에 카테고리/사진/설명/가격/옵션/일정 모두).
- 현재 코드: `WizardPage` — 7단계 멀티스텝 마법사 (`/seller/new`).
- **질문**: 판매 상품 등록을 7단계 마법사 → 단일 스크롤 화면으로 교체할지 결정 필요.
  - 교체한다면: `WizardPage` 전면 재작성, 각 단계의 검증 로직을 단일 form으로 통합.
  - 현행 유지라면: 기능은 동일하되 UI 구조 차이가 남으며 반영점검표 43% 그대로.
- 현행 `WizardPage` 구조 유지 (대규모 재작성 대신 기능 보존 우선).

### AI 상품분석 / AI 처리 상태 화면 — 경로 미매핑
- Figma: "AI 상품 분석" 화면 (AI 분석 완료 결과, 카테고리 추천, 사진에서 찾은 정보), "AI 처리 상태 · 상품 분석 중" 화면 (분석 중 스켈레톤), "AI 처리 상태 · 분석 실패와 재시도" 화면.
- 현재 코드: 이 세 화면에 해당하는 라우트 없음. 위자드 플로우 내 임시 처리 추정.
- **질문**: AI 상품분석 화면을 `/seller/ai-analysis/:id` 등 별도 라우트로 추가할지 결정 필요.
  - 추가한다면: 위자드 플로우에서 사진 등록 후 AI 분석 단계로 전환하는 연결 로직 필요.
  - 현행 유지라면: 세 화면 모두 반영 보류 처리.
- 현행 구조 유지 (AI 분석은 위자드 플로우와 연동 결정 후 진행 권장).
